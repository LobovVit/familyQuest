# FamilyQuest

Семейный планер, рейтинги, награды и совместные занятия. Go, PostgreSQL, React и TypeScript. Одна установка — одна семья.

## Локальный запуск

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
# Задайте POSTGRES_PASSWORD, DATABASE_URL и SESSION_SECRET.
docker compose config --quiet
docker compose up --build -d
```

Приложение: `http://localhost:8088`; API: `127.0.0.1:8081`; PostgreSQL: `127.0.0.1:5433`. Изменить порты можно через `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`.

Локальная конфигурация явно подключает демонстрационный seed. Используйте его только для разработки. Production-образ его не содержит; для новой production-базы нужен индивидуальный bootstrap, описанный в [эксплуатации](docs/operations.md).

Остановка с сохранением данных: `docker compose down`. Команда `down -v` удаляет базу — не используйте её для обновления или исправления пароля.

## Настройки

`.env` игнорируется Git. `POSTGRES_PASSWORD` — пароль PostgreSQL; тот же пароль в `DATABASE_URL` должен быть URL-encoded при наличии специальных символов. В Compose hostname БД — `postgres`, при запуске Go на хосте — `localhost:5433`.

`SESSION_SECRET` должен быть случайным секретом не менее 32 байт; `SESSION_TTL` по умолчанию `12h`. `CORS_ORIGIN` — разрешённый origin браузера. Для production задайте `PUBLIC_HOST` и существующую сеть `TRAEFIK_NETWORK`.

```bash
docker compose -f docker-compose.prod.yml config --quiet
docker compose -f docker-compose.prod.yml up --build -d
```

Production не публикует API и БД. Внешний reverse proxy завершает TLS, Traefik направляет запросы в web. API и web работают не от root, с read-only filesystem и сброшенными capabilities; PostgreSQL использует постоянный volume.

## Разработка и проверки

Go-версия указана в `backend/go.mod`, frontend использует Node 24.

```bash
go -C backend test -race ./...
go -C backend vet ./...
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
```

Интеграционные Go-тесты требуют `FAMILYQUEST_TEST_DATABASE_URL`, указывающий **только на отдельную одноразовую PostgreSQL**: они удаляют тестовые данные. Без этой переменной DB-тесты пропускаются. CI поднимает собственную PostgreSQL и выполняет их вместе с unit-тестами, проверкой форматирования и сборкой обоих Docker-образов.

Миграции лежат в `backend/migrations`, выполняются по порядку и учитываются в `schema_migrations`. Не изменяйте применённые миграции; добавляйте следующую.

### Спорт для всей семьи

После входа выберите раздел **«Спорт · занятия и прогресс»**. Запишите участника,
дату, вид спорта и длительность занятия; при необходимости добавьте дистанцию,
упражнения (подходы, повторения, вес в кг) и заметки. Разные подходы одного
упражнения можно записывать отдельными строками. Нулевой вес означает занятие
без дополнительного отягощения.

Доступны фильтры по участнику, виду спорта и периоду, суммарные минуты и километры,
активность по неделям и сравнение первого/последнего результата в упражнениях
выбранного участника. Максимальный записанный вес не является оценкой силы:
учитывайте число повторений и условия выполнения. Карточки можно редактировать,
архивировать и восстанавливать; архив смотрится отдельно от активной истории.

Все члены семьи видят журнал. Родители могут вести занятия за любого активного
члена семьи; ребёнок создаёт и меняет только свои записи, в том числе заведённые
родителем. Школьная роль доступа не имеет. Спорт хранится в `family_entries`
как типизированный `sport` и входит в резервную копию приложения.
Новая миграция базы не требуется; сервер и интерфейс обновляются вместе.

### Обзор без входа

В режиме просмотра под рейтингами показаны спорт, привычки и приключения:
занятия с понедельника по выбранную дату с итогами минут и километров,
привычки по расписанию на выбранный день с отметившимися участниками,
приключения и одобренные идеи с числом выполненных шагов. Архивные карточки
не показываются. Дата меняется общим переключателем вверху страницы.

`GET /api/family/overview?date=YYYY-MM-DD` доступен без PIN, как рейтинги:
он возвращает названия, участников, даты и показатели для этого обзора.
Описания, заметки, самочувствие, медиа, обсуждения и неодобренные идеи
в публичный ответ не включаются. Полные семейные карточки и операции изменения
по-прежнему требуют входа с подходящей ролью. Для выпуска обновите API и frontend.

### Математика и награды

В профиле ребёнка доступны «Математика · учимся считать» и приглашение начать
занятие в планере. Операции: сложение, вычитание, умножение, деление. Уровни
повторяют MathKidsApp: лёгкий (8 примеров), средний (12), сложный (15), в столбик
(8). Обычные примеры решаются вводом числа или выбором из четырёх вариантов.
Отрицательные ответы можно включить для обычного вычитания. Деление всегда
без остатка; дробный результат не округляется и не отбрасывается.

В столбик проверяются ответ и промежуточные действия: переносы/заёмы для
сложения/вычитания, переносы и частичные произведения для умножения. Для деления
есть «Только итог», «Шаги» и «Полный» со сносом цифр. Поля выбираются касанием,
есть крупная цифровая клавиатура. Пустой перенос означает ноль; остальные шаги
нужно заполнить. Ошибочный ответ показывает разбор без штрафа и без награды.
Занятие можно продолжить после перезагрузки или закончить досрочно, сохранив
заработанное. Одновременно у ребёнка одно незавершённое занятие.

Награды за новые действия:

| Действие | Звёзды | Улыбки | Ограничение |
| --- | ---: | ---: | --- |
| Верный математический пример | 1–5 | 0 | До 30 звёзд на ребёнка за день во всех новых занятиях |
| Запись спортивного занятия | 30 | 2 | Один раз на участника и дату, даже при нескольких тренировках |
| Отметка привычки по расписанию | 5 | 1 | Один раз на привычку, участника и дату |
| Завершение всех шагов приключения | 40 | 3 | Один раз каждому назначенному участнику; без назначений — авторам выполненных шагов |

Награды входят в существующие рейтинги дня/недели/месяца. «Мои звёзды и улыбки»
показывает последние 200 начислений. Существовавшие до обновления записи не
пересчитываются задним числом. Архивирование, восстановление, правка карточки и
повторная отправка запроса не дают повторный бонус и не отнимают заработанное.
Даты математических наград определяются сервером по Europe/Minsk (UTC+3).

Миграция `005_learning_rewards.sql` добавляет занятия и журнал начислений.
Резервная копия v4 включает оба раздела и версию правил математики; v3 сохраняет старые начисления. v1/v2 по-прежнему импортируются,
заменяя всю семью и очищая отсутствующую в них историю математики/новых наград.


### Баланс для младшего школьника

Это стартовая продуктовая шкала, а не возрастная норма. Стоимость существующих дел
сохранена: простые детские дела 15–20 ⭐, обычные 25–35 ⭐, длительные 40–60 ⭐.
Подтверждение начисляет `baseValue × средняя оценка / 5`; несколько оценок
усредняются, а не суммируют награду. Улыбки за дела отдельно не начисляются:
каждая оценка поведения даёт 1–5 улыбок, повторная оценка того же человека за дату
заменяет предыдущую. Помощь взрослого в совместном деле не повод снижать оценку.

| Математика | Ввод ответа | Выбор из 4 |
| --- | ---: | ---: |
| Лёгкое сложение / вычитание | 1 | 1 |
| Лёгкое умножение / деление | 2 | 1 |
| Среднее сложение / вычитание | 2 | 1 |
| Среднее умножение / деление | 3 | 2 |
| Сложное сложение / вычитание | 3 | 2 |
| Сложное умножение / деление | 4 | 3 |

В столбик: сложение/вычитание 3 ⭐, умножение 4 ⭐; деление — только итог 3 ⭐,
шаги 4 ⭐, полный разбор 5 ⭐. Правильными должны быть все запрошенные шаги.
Остаток дневного бюджета может уменьшить последнюю награду (например, 2 вместо 4).
После 30 ⭐ правильные ответы по-прежнему сохраняются, но новые звёзды за день
не начисляются. Смена занятия/устройства и сетевой повтор не обходят лимит;
новый день начинается в 00:00 Europe/Minsk. Старые занятия без `rewardVersion`
сохраняют прежние 1/2/3 ⭐; уже полученные за них звёзды учитываются при проверке
бюджета новых занятий. Ошибки не отнимают звёзды, скорость и серии не увеличивают их.

Практический ориентир: дело на 30 ⭐ при оценке 4 = 24 ⭐; 8 простых примеров = 8 ⭐;
спорт = 30 ⭐ + 2 🙂; три привычки = 15 ⭐ + 3 🙂. Стоимость существующих призов
сохранена. Одно действие следует учитывать либо как дело, либо в спорте/привычках:
разные карточки с одинаковым смыслом автоматически не объединяются.

Правила должны быть понятными, а цели достижимыми; награду стоит сопровождать
конкретной похвалой за усилие. Основа подхода: [AAP — Positive Reinforcement Through Rewards](https://www.healthychildren.org/English/family-life/family-dynamics/Pages/Positive-Reinforcement-Through-Rewards.aspx).

### Личные устройства и вход

При первом входе выберите профиль, введите его PIN и отметьте **«Это моё устройство»**.
Назовите браузер, например «iPad Макса» или «MacBook мамы». Для ребёнка дополнительно
нужны выбор родителя и его PIN. Для роли `school` запоминание недоступно.
На личном устройстве профиль открывается автоматически; вход действует 90 дней
без использования и продлевается при обращении к приложению. PIN не сохраняется.
Один профиль может использовать несколько устройств. Разные браузеры и отдельная
установка на домашний экран могут иметь отдельное хранилище — подключайте их отдельно.

Без галочки действует обычный временный вход. Переключение профиля требует его PIN
и заменяет прежнюю привязку этого браузера. **«Выйти» забывает вход на устройстве**;
чтобы сохранить привязку, просто закройте вкладку. Очистка данных сайта или закрытие
приватного браузера может удалить запомненный вход.

Родитель: **Настройки пользователей → Устройства семьи**. Видны профиль, название,
последнее использование и срок входа. «Отключить» требует повторного PIN текущего
родителя; отключение текущего устройства выводит из профиля. Смена PIN отключает
все устройства этого профиля. Восстановление JSON-backup отключает устройства всей
семьи; их секреты в выгрузку не включаются. Смена PIN и восстановление backup также
требуют повторного родительского подтверждения.

Это собственная авторизация FamilyQuest по PIN. Вход с Apple ID и passkeys/Face ID/
Touch ID пока не подключены.
