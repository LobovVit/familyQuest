## Локальный запуск

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
# Задайте POSTGRES_PASSWORD, DATABASE_URL и SESSION_SECRET.
docker compose config --quiet
docker compose up --build -d
```

Приложение: `http://localhost:8088`; API: `127.0.0.1:8081`; PostgreSQL: `127.0.0.1:5433`. Изменить порты можно через `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`.

Локальная конфигурация явно подключает демонстрационный seed. Используйте его только для разработки. Production-образ его не содержит; для новой production-базы нужен индивидуальный bootstrap, описанный в [эксплуатации](docs/operations.md).

Остановка с сохранением данных: `docker compose down`. Команда `down -v` удаляет базу — не используйте её для обновления или исправления пароля.

## Настройки

`.env` игнорируется Git. `POSTGRES_PASSWORD` — пароль PostgreSQL; тот же пароль в `DATABASE_URL` должен быть URL-encoded при наличии специальных символов. В Compose hostname БД — `postgres`, при запуске Go на хосте — `localhost:5433`.

`SESSION_SECRET` должен быть случайным секретом не менее 32 байт; `SESSION_TTL` по умолчанию `12h`. `CORS_ORIGIN` — разрешённый origin браузера. Для production задайте `PUBLIC_HOST` и существующую сеть `TRAEFIK_NETWORK`.

```bash
docker compose -f docker-compose.prod.yml config --quiet
docker compose -f docker-compose.prod.yml up --build -d
```

Production не публикует API и БД. Внешний reverse proxy завершает TLS, Traefik направляет запросы в web. API и web работают не от root, с read-only filesystem и сброшенными capabilities; PostgreSQL использует постоянный volume.

## Разработка и проверки

Go-версия указана в `backend/go.mod`, frontend использует Node 24.

```bash
go -C backend test -race ./...
go -C backend vet ./...
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
```

Интеграционные Go-тесты требуют `FAMILYQUEST_TEST_DATABASE_URL`, указывающий **только на отдельную одноразовую PostgreSQL**: они удаляют тестовые данные. Без этой переменной DB-тесты пропускаются. CI поднимает собственную PostgreSQL и выполняет их вместе с unit-тестами, проверкой форматирования и сборкой обоих Docker-образов.

Миграции лежат в `backend/migrations`, выполняются по порядку и учитываются в `schema_migrations`. Не изменяйте применённые миграции; добавляйте следующую.

### Спорт для всей семьи

После входа выберите раздел **«Спорт · занятия и прогресс»**. Запишите участника,
дату, вид спорта и длительность занятия; при необходимости добавьте дистанцию,
упражнения (подходы, повторения, вес в кг) и заметки. Разные подходы одного
упражнения можно записывать отдельными строками. Нулевой вес означает занятие
без дополнительного отягощения.

Доступны фильтры по участнику, виду спорта и периоду, суммарные минуты и километры,
активность по неделям и сравнение первого/последнего результата в упражнениях
выбранного участника. Максимальный записанный вес не является оценкой силы:
учитывайте число повторений и условия выполнения. Карточки можно редактировать,
архивировать и восстанавливать; архив смотрится отдельно от активной истории.

Все члены семьи видят журнал. Родители могут вести занятия за любого активного
члена семьи; ребёнок создаёт и меняет только свои записи, в том числе заведённые
родителем. Школьная роль доступа не имеет. Спорт хранится в `family_entries`
как типизированный `sport` и входит в существующую резервную копию v2.
Новая миграция базы не требуется; сервер и интерфейс обновляются вместе.

### Обзор без входа

В режиме просмотра под рейтингами показаны спорт, привычки и приключения:
занятия с понедельника по выбранную дату с итогами минут и километров,
привычки по расписанию на выбранный день с отметившимися участниками,
приключения и одобренные идеи с числом выполненных шагов. Архивные карточки
не показываются. Дата меняется общим переключателем вверху страницы.

`GET /api/family/overview?date=YYYY-MM-DD` доступен без PIN, как рейтинги:
он возвращает названия, участников, даты и показатели для этого обзора.
Описания, заметки, самочувствие, медиа, обсуждения и неодобренные идеи
в публичный ответ не включаются. Полные семейные карточки и операции изменения
по-прежнему требуют входа с подходящей ролью. Для выпуска обновите API и frontend.
