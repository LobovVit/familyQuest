# Семейная жизнь в FamilyQuest

Раздел **«Семья · привычки и приключения»** доступен после входа родителю или ребёнку. Одна установка сервиса обслуживает одну семью, как и существующие обязанности. Школьный и анонимный режимы не имеют доступа к семейным карточкам, заметкам и медиа.

## Возможности

- **Сегодня вместе:** привычки по дням недели начиная с выбранной даты, запланированные приключения, согласованные идеи и семейные советы. Общая дата в верхней панели управляет планом и датой отметок. Воспоминания прошлых лет показываются в годовщину события.
- **Чем займёмся:** 12 подготовленных сценариев с фильтрами времени, возраста младшего участника, места, активности, бюджета и поиска по интересу/материалам. Карточки содержат подготовку, шаги, роли для младших и старших и вопрос для обсуждения. Выбранный сценарий открывается в редакторе с распределением ролей.
- **Приключения:** дата, общая цель, участники и до 30 шагов с ответственным или режимом «Вместе». Каждый отмечает свои шаги; общий шаг может отметить любой участник занятия. Завершённое приключение добавляет домик в общий сад.
- **Привычки:** дни недели, начало, желаемое время, облегчённый вариант, личные отметки участия и история без обнуления после пропуска. Шаблоны: прогулка, чтение, порядок. Отметка идемпотентна для участника и даты; в саду общий день привычки учитывается один раз.
- **Наши ценности:** собственная ценность семьи и конкретный поступок. Есть готовые варианты заботы, уважения, благодарности и любознательности, отметки участия и обсуждение. Оценок «хорошести» и соревнования детей нет.
- **Мастерская навыков:** посмотрел → сделал вместе → попробовал сам → объяснил другому. У каждого участника собственный последовательный прогресс. Готовые маршруты: завтрак, покупки, проверка информации и уход за растением.
- **Наши идеи:** предложение ребёнка видно семье сразу; начинать его шаги можно после согласования родителем. При создании ребёнком обычного приключения сервер автоматически делает его предложением. Изменение согласованного предложения ребёнком требует нового согласования.
- **Семейный совет:** вопросы для обсуждения, заметки участников, одна договорённость и следующее совместное занятие с переходом к планированию. Личные ответы необязательны.
- **Капсула памяти:** история или смешная фраза, дата, необязательное фото и голосовая запись. Поиск, продолжение приключения, годовщины и архив. Кнопка «Сохранить воспоминание» переносит название, участников и ценность исходной карточки.
- **Наш сад:** дни участия, завершённые приключения, освоенные навыки, договорённости совета и воспоминания. Архив не отнимает достижения. Видны число занятий, которые хотят повторить, и число продолжаемых привычек. Визуально показаны последние 100 достижений; история в карточках сохраняется полностью.

## Напоминания и медиа

Напоминание привычки скачивается файлом `.ics` для импорта в личный календарь. Время локальное, первая дата совпадает с выбранным днём недели. В календаре создаётся повторяющееся событие с уведомлением. Это не push-уведомления из веб-приложения. При изменении/архивировании привычки импортированное событие нужно изменить/удалить в календаре самостоятельно.

Фото JPEG/PNG до 15 МБ уменьшается в браузере до 960 пикселей и сохраняется как JPEG, не более 500 КБ. Аудио MP3/WAV/OGG/WebM/M4A загружается готовым коротким файлом до 500 КБ; записи с микрофона внутри приложения нет. Фото и аудио сохраняются в PostgreSQL вместе с карточкой, внешние ссылки и хранилища не используются. Все заметки и медиа видны родителям и детям данной семьи. Внешние AI-сервисы во время использования раздела не вызываются.

## API и хранение

Миграция `003_family_life.sql` добавляет `family_entries`. Это агрегат карточки: типизированное содержимое и события в JSONB, идентификатор автора, серверное время и отдельная версия в SQL. Авторизация и переходы состояния находятся в application/domain; PostgreSQL-адаптер атомарно обновляет строку с условием `WHERE id = ... AND version = ...`. При конфликте возвращается HTTP 409, клиент перечитывает данные и предлагает открыть свежую карточку. Шаги с историей нельзя заменить при редактировании.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/family` | Все активные и архивные карточки семьи |
| `POST /api/family` | `{kind, draft}` — создать карточку |
| `PUT /api/family/{id}` | `{version, draft}` — изменить описание/план |
| `POST /api/family/{id}/actions` | `{version, action, date?, step?, note?, easy?}` |

Действия: `checkin`, `step`, `stage`, `reflection`, `repeat`, `approve`, `archive`, `restore`. Автор действия всегда берётся из сессии. Клиент не может передать автора, готовую историю или флаг согласования. Изменять и архивировать карточку может автор или родитель; согласовывать — только родитель. Участник с ролью school не читает и не изменяет раздел. Неизвестные JSON-поля, несколько JSON-объектов, некорректные даты, роли и превышения размера отклоняются.

История ограничена 10 000 событиями на карточку, заметка — 2 000 символами, описание — 4 000. При заполнении карточку можно архивировать и создать новую. Запросы семейного API ограничены 2 МБ, импорт резервной копии — 64 МБ. Для большого архива с большим числом медиа следует использовать резервное копирование PostgreSQL; JSON-импорт ограничен размером запроса.

## Резервное копирование

Версия JSON-копии повышена до 2 и включает `familyEntries`, события и медиа. Экспорт использует согласованный снимок, импорт выполняется в одной транзакции и восстанавливает последовательность идентификаторов. Копии версии 1 принимаются: отсутствие `familyEntries` означает пустой семейный раздел после полной замены данных. Как и раньше, импорт заменяет всю базу данных приложения; это отражено в подтверждении интерфейса. Правила восстановления учётных данных описаны в основной документации.

## Проверка

```sh
# Запускать из корня проекта; URL только отдельной одноразовой тестовой БД.
FAMILYQUEST_TEST_DATABASE_URL='postgres://.../disposable_database?sslmode=disable' go -C backend test -race ./...
go -C backend vet ./...
npm --prefix frontend test
npm --prefix frontend run lint
npm --prefix frontend run build
```

Тесты проверяют ограничения доступа, подмену автора/согласования, последовательность личных навыков, идемпотентность привычки, неизменность истории после архива, конкурентные записи на PostgreSQL, резервное копирование v2 и импорт v1, фильтры занятий, локальные даты, календарные напоминания и запоздалые ответы API. Интеграционные тесты очищают только БД, явно переданную в `FAMILYQUEST_TEST_DATABASE_URL`.
