# Пилот семейного помощника

Пилот предназначен для изолированного SaaS-стенда FamilyQuest с HTTPS и двумя синтетическими семьями. Примените миграцию `013_helper_access.sql` штатным мигратором до запуска новой версии API. Для проверки используйте активные тестовые семьи с доступом к записи. В интеграционном тесте доступ задаётся напрямую в одноразовой базе PostgreSQL.

## Сценарий

1. Создайте семьи «Альфа» и «Бета». Для каждой подготовьте родительский и детский профили, два дела на одну дату и план на следующий день. Используйте нейтральные названия, например «Полить растение» и «Протереть стол». Добавьте синтетические оценки и описание дела, чтобы проверить, что они скрыты.
2. В семейном веб-интерфейсе войдите как родитель «Альфы». В разделе «Настройки» откройте блок «Семейный помощник», выберите одно дело и выдайте доступ на 24 часа. Повторите для «Беты» с другим названием. Метку видит родитель.
3. В отдельных чистых браузерных профилях откройте `/helper`. Оператор стенда вручную вводит соответствующий тестовый код. Проверьте, что видны только название и дата выбранного дела. Проверьте, что вторая семья, соседнее дело и следующий экземпляр повторяющегося дела скрыты.
4. Проверьте, что детский и школьный профили не могут управлять доступом. Из сессии помощника запросите семейные разделы, включая профили, историю, баллы, занятия, экспорт и настройки. Ожидается отказ.
5. Оставив обе страницы помощника открытыми, отзовите код «Альфы». Следующий запрос со старым кодом должен вернуть `401`. В активной вкладке список исчезает при возврате фокуса или очередной проверке, выполняемой каждые 15 секунд. Страница «Беты» продолжает работать.
6. После проверки отзовите оставшиеся коды. Для стенда используйте ручной ввод тестовых кодов и синтетические профили. Рассылки и биллинг в сценарии не участвуют.

## Границы доступа

Код действует как предъявительский секрет. Передавайте его конкретному помощнику приватно. Приложение показывает его при выдаче и хранит только хеш на сервере. Страница помощника держит код в памяти вкладки и отправляет его в заголовке авторизации без семейных cookies. Код не попадает в ссылку.

В пилоте помощник только читает выбранные экземпляры дел. Название фиксируется при выдаче доступа, а дата берётся из выбранного экземпляра. Доступ к другим экземплярам повторяющегося дела требует отдельного назначения. Чтобы изменить набор, отзовите код и выдайте новый. Если дело, назначение или исходный профиль отключены, дело исчезает из списка. Отзыв блокирует будущие ответы сервера и не удаляет уже прочитанные данные с устройства получателя.

Обычный экспорт семьи не включает коды и назначения помощника. Восстановление через импорт отзывает все доступы помощников в этой семье. При восстановлении полного снимка базы перед открытием стенда удалите сохранённые доступы помощников из восстановленных семей.

## Локальная проверка

Запустите `go test ./...` и `go build ./...` в `backend`, а также `npm test` и `npm run build` в `frontend`. Для интеграционного сценария задайте `FAMILYQUEST_TEST_DATABASE_URL` на одноразовую базу PostgreSQL и запустите `go test ./internal/store -run '^TestHelperPilotIsolation$' -count=1 -v` из `backend`. Тест проходит через шлюз доступа и закрытый API с двумя схемами семей и совпадающими локальными идентификаторами дел.
