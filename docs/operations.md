# Эксплуатация и восстановление

## Первый production-запуск

Production-образ не содержит демонстрационный seed. Пустой `FAMILYQUEST_SEED_FILE` отключает импорт. Автоматического создания взрослого с известным PIN нет. Для новой базы подготовьте защищённый JSON-bootstrap с индивидуальным PIN хотя бы одного взрослого; не используйте демонстрационные аккаунты.

Минимальная структура (замените значения до запуска):

```json
{
  "version": 2,
  "participants": [
    {
      "id": 1,
      "name": "Имя взрослого",
      "role": "parent",
      "pinCode": "<6 цифр>",
      "active": true,
      "createdAt": "2026-09-19T00:00:00Z"
    }
  ]
}
```

Поместите файл вне Git и ограничьте права чтения. Во временном Compose override подключите его read-only к `/app/bootstrap.json` и задайте `FAMILYQUEST_SEED_FILE: /app/bootstrap.json` у api. После успешного импорта уберите override и файл с сервера. На уже заполненной базе seed не применяется. Не удаляйте существующий volume ради смены учётных данных или повторной инициализации.

## Резервное копирование

JSON-export содержит бизнес-данные и семейные медиа, но не PIN и не bcrypt-хеши. Он предназначен для восстановления поверх соответствующей установки. Восстанавливаемый участник сохраняет текущий хеш только при совпадении ID, имени и роли. Legacy-поле `pinCode` допускается при подготовленном bootstrap и сразу хешируется; выгрузка его не добавляет.

Импорт версии 1 поддерживается для совместимости; семейные карточки отсутствующего раздела не сохраняются при полной замене. Версия 2 содержит `familyEntries`; текущая версия 3 дополнительно содержит `mathSessions` и `activityRewards`. Импорт версий 1/2 очищает отсутствующую в них историю обучения и дополнительных начислений. Перед импортом сохраните актуальную копию. Импорт отзывает ранее выданные сессии; потребуется вход с сохранённым или новым PIN.

Для полного disaster recovery отдельно резервируйте PostgreSQL, конфигурацию и секреты. Пример создания дампа без вывода содержимого в терминал:

```bash
umask 077
docker compose -f docker-compose.prod.yml exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > familyquest.dump
```

Дамп содержит чувствительные данные и хеши PIN: храните его зашифрованным вне сервера. Регулярно проверяйте восстановление в отдельной базе. Смена `SESSION_SECRET` после восстановления полного дампа гарантированно отзывает прежние JWT. Автоматическая ротация, offsite-копирование и расписание backup в репозитории не реализованы.

## Сеть и ограничения

В production наружу направляется только web через существующий Traefik. TLS завершает внешний reverse proxy. PostgreSQL и API доступны во внутренней Docker-сети; приложение не настраивает VPN или публичный reverse proxy. Локальная Compose-конфигурация публикует порты только на loopback.

Публичные `participants` и `leaderboard` раскрывают имена и агрегированные результаты посетителю без PIN. Это существующий режим просмотра; для закрытого семейного использования ограничьте доступ ко всей установке на внешнем proxy/VPN. CORS не заменяет контроль доступа.

PIN имеет шесть цифр. Rate limiting действует на Nginx `/api/session`; прямой доступ к API должен оставаться внутренним. За цепочкой proxy лимит применяется по адресу ближайшего соединения, пока администратор явно не настроит доверенные real-IP источники. При необходимости отдельный per-user/global limiter следует размещать на контролируемой внешней границе.

Размер JSON-import ограничен 64 MiB; для большей базы используйте PostgreSQL backup. Коллекции пока не имеют пагинации, фото/аудио хранятся в JSONB. Для большой медиатеки потребуются отдельное хранилище и другой формат backup.

## Обновление

`scripts/update-home.sh` проверяет чистоту checkout (кроме явного `ALLOW_DIRTY=1`), выполняет fast-forward, проверяет Compose, пересобирает и ждёт healthcheck. Скрипт не откатывает миграции автоматически. Перед обновлением сделайте backup. `HEALTH_HOST`/`HEALTH_URL` должны указывать на нужную установку; значение по умолчанию относится к домашнему серверу.

Проверяйте `docker compose ... ps`, `/api/health`, вход, сохранение и повторную загрузку данных. HTTP health подтверждает доступность БД, но не полноту пользовательских сценариев. Push в GitHub запускает CI; самостоятельного production deploy в workflow нет.

## Индивидуальные PIN при первоначальном запуске

Локальные `backend/seed/familyquest-private.json` и `docker-compose.override.yml`
исключены из Git. Приватный JSON-bootstrap храните с правами `600`; override
задаёт `FAMILYQUEST_SEED_FILE: /app/seed/familyquest-private.json` для dev Compose.
Для production используйте отдельный override с read-only mount этого файла,
как описано выше. Эти настройки применяются только к пустой базе. В заполненной
базе PIN меняются через API/настройки пользователей, с отзывом прежних сессий.
Не копируйте реальные PIN в демонстрационный seed, документацию или коммиты.

## iPad

Интерфейс адаптирован для портретного и альбомного вида: проверочные размеры
820×1180 и 1180×820 CSS px. На сенсорных устройствах и экранах до 1180 px высота
кнопок и полей не менее 44 px, шрифт ввода не менее 16 px; формы тренировок
переносят название упражнения на отдельную строку. Окно PIN ограничено динамической
высотой экрана и допускает прокрутку при открытой клавиатуре. Проверка в браузере
с этими размерами не заменяет проверку Safari на физическом iPad.
