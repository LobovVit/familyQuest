# Подключение ИИ-агента к FamilyQuest

MCP позволяет агенту читать фактические результаты и по просьбе пользователя отмечать дела. Сервер не вызывает внешние LLM: модель выбирается в клиенте пользователя.

## Выдать подключение

1. Войти в FamilyQuest как родитель и открыть **Настройки → ИИ-подключения · MCP**.
2. Выбрать профиль, указать название агента. По умолчанию включено **Только чтение результатов**. Снимите флажок, если агенту разрешены отметки в пределах роли.
3. Нажать **Создать ключ MCP** и подтвердить родительский PIN.
4. Сохранить показанный ключ в секретном хранилище MCP-клиента. Он показывается один раз, в базе хранится только запись делегирования, без самого токена.
5. Настроить в клиенте Streamable HTTP endpoint `https://ВАШ-ДОМЕН/api/mcp` и HTTP-заголовок `Authorization: Bearer КЛЮЧ`.

Пример конфигурации клиента, поддерживающего такой формат:

```json
{
  "mcpServers": {
    "familyquest-child": {
      "url": "https://ВАШ-ДОМЕН/api/mcp",
      "headers": {
        "Authorization": "Bearer ЗНАЧЕНИЕ_ИЗ_СЕКРЕТНОГО_ХРАНИЛИЩА"
      }
    }
  }
}
```

Названия полей конфигурации зависят от клиента. Требуется поддержка собственного Bearer-заголовка; OAuth discovery/динамическая регистрация клиентов не реализованы. Не передавайте ключ в чат, URL, Git или общие настройки. Для каждого профиля/агента создайте отдельное подключение. У агента нет инструмента переключения профиля.

Ключ действует 90 дней без автоматического продления. Родитель может немедленно отозвать его кнопкой **Отключить**. Смена PIN, деактивация профиля, изменение роли и восстановление резервной копии также делают прежние ключи недействительными. Выход из браузера не отзывает отдельное делегирование MCP. Самостоятельно управлять ключами ребёнок и школа не могут.

## Права и инструменты

| Инструмент | Родитель | Ребёнок | Школа |
|---|---|---|---|
| `get_profile` | Свой профиль и режим ключа | Свой профиль и режим ключа | Свой профиль и режим ключа |
| `get_results` | Планер и результаты семьи | Только свои задачи и результаты | Планер и результаты семьи, как в существующем REST API |
| `get_activities` | Привычки, спорт, навыки, шаги приключений и прогресс | Доступные карточки и свои отметки | Нет |
| `get_learning_results` | Свои результаты или выбранного участника семьи | Только свои | Нет |
| `complete_task` | Только свои задачи | Только свои задачи | Нет |
| `mark_activity` | Отметка от своего имени | Отметка от своего имени | Нет |
| `confirm_task` | Чужая выполненная задача, оценка 1–5 | Нет | Нет |

Ключ «только чтение» не предоставляет три последних инструмента. Школьный профиль всегда получает только чтение, независимо от флажка. Дата `YYYY-MM-DD` задаётся явно; неоднозначную дату или название агент должен уточнить. Для отметки карточки нужны ID и актуальная версия из `get_activities`; после конфликта следует перечитать карточку и согласовать действие заново. Шаг приключения нумеруется с нуля, этап навыка — от 1 до 4.

Эти ограничения проверяются также в application-сценариях, независимо от списка инструментов: прямой вызов изменения с делегированием «только чтение» отклоняется. MCP с записью не может начать/завершить обучение, получить родительское подтверждение, изменить профили или утвердить/архивировать карточку. Семейные отметки используют дату Минска и не принимают будущую дату.

Примеры запросов агенту:

- «Покажи мои дела на 2026-10-19 и отметь “Убрать комнату” выполненным».
- «Отметь мою привычку “Зарядка” за 2026-10-19».
- «Сравни мои результаты за день, неделю и месяц на 2026-10-19».
- «Проанализируй сохранённые результаты обучения ребёнка, не выполняя упражнения за него».

Результаты содержат данные для анализа клиентской моделью, а не автоматически сгенерированные выводы. Инструменты не позволяют пройти обучение, выдать звёзды напрямую, менять PIN/профили, создавать ключи или выгружать бэкапы. Приватные обсуждения, фотографии и аудио не входят в ответ `get_activities`.

## Архитектура и эксплуатация

- Официальный [MCP Go SDK](https://github.com/modelcontextprotocol/go-sdk), stateless Streamable HTTP, JSON-ответы. Состояние MCP-сессии не используется как авторизация.
- Каждый запрос проверяет подпись JWT, срок токена, семью, актуальную роль, активность и `session_version` профиля, существование и срок неотозванного делегирования. Права берутся из текущей серверной записи.
- Для SaaS таблица `mcp_grants` создаётся миграцией `010_mcp_grants.sql` внутри схемы каждой семьи. Используется существующий family-scoped repository и runtime role. Требуется штатный запуск миграций оператором до обновления Core/Access.
- В Access исключение из браузерного SSO действует только для `/api/mcp` после успешной приватной introspection с MCP-делегированием. Обычный браузерный токен не подходит для MCP. MCP-токен не подходит для защищённого REST API и смены профиля.
- При истёкшей подписке чтение истории через MCP остаётся доступно, запись проверяет `service_policy` в существующих application use cases. Отзыв ключей также остаётся доступен. При блокировке семьи Access отклоняет подключения.
- Origin, если присутствует, должен соответствовать хосту приложения; cookie-авторизация на MCP не поддерживается. Для внешних клиентов нужен HTTPS. Открывать приватный Core или передавать клиенту `ACCESS_SHARED_SECRET` не требуется.
- Существующие доменные правила проверяют владельца задачи, запрет самоутверждения, назначение шага, актуальную версию и допустимый переход. В истории остаётся действующий профиль. При ошибках инструменты возвращают безопасные сообщения, без SQL/секретов.
- Ключи не экспортируются в резервную копию; восстановление удаляет делегирования через FK cascade.

Интеграционные проверки `TestMCPProfileDelegation` и `TestMCPSaaSAccessIsolationAndExpiry` используют disposable PostgreSQL и официальный SDK-клиент: реальные tools/list и tools/call, изоляция ролей/семей, отзыв, смена PIN, Origin, REST-границы и ограничения подписки.
