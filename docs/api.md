# API и права

С версии 0.2.0 доступен отдельный [сервис доступа перед API](access-service.md) с разделением SQL-прав и сетей. В этом режиме после подключения семей используйте `grant-core`; `grant-runtime` предназначен для SaaS без прокси.

Основная таблица описывает домашний режим. В SaaS все семейные маршруты, включая списки и рейтинги, требуют сессию конкретной семьи; `familyId` берётся из проверенного токена/устройства. Без семейной сессии доступны конфигурация, версия, health и маршруты входа взрослого; SSO callback и back-channel logout проверяют собственные протокольные credentials. [Полная модель](saas-architecture.md), [SSO](sso.md).

Базовый путь — `/api`. Вход: `POST /api/session` с JSON `{ "participantId": 1, "pin": "<6 цифр>" }`. Ответ содержит `participant` и `token`. Защищённые запросы передают `Authorization: Bearer <token>`.

| Endpoint | Доступ / действие |
| --- | --- |
| `GET /health` | Без входа; 503, если PostgreSQL недоступен |
| `POST /session` | Без входа; проверка PIN и выпуск JWT |
| `GET /family/overview?date=YYYY-MM-DD` | Без входа; названия, участники и прогресс спорта, привычек и приключений, без заметок/медиа |
| `GET /participants` | Без входа; активные участники без PIN/хешей |
| `GET /leaderboard?period=day\|week\|month&date=YYYY-MM-DD` | Без входа; общий рейтинг |
| `GET /chores`, `/assignments`, `/tasks`, `/week-plan`, `/behavior-ratings`, `/rewards` | Любая действующая сессия |
| `POST /participants`, `PUT /participants/{id}/pin`, `DELETE /participants/{id}` | Только взрослый; последнего взрослого удалить нельзя |
| `POST /chores`, `PUT /chores/{id}`, `POST /assignments` | Только взрослый |
| `POST /tasks/{id}/complete` | Только исполнитель, состояние pending/needs_work |
| `POST /tasks/{id}/confirm` | Взрослый, чужая выполненная задача, rating от 1 до 5 |
| `POST /behavior-ratings` | parent/child, targetParticipantId другого участника, rating от 1 до 5 |
| `POST /rewards`, `DELETE /rewards/{id}` | Только взрослый |
| `GET /backup`, `POST /backup` | Только взрослый; импорт заменяет все прикладные данные |
| `GET /family`, `POST /family`, `PUT /family/{id}`, `POST /family/{id}/actions` | parent/child; дополнительные правила автора, участника и версии карточки |

Объекты `participantId` и `raterParticipantId`, присланные как автор действия, не дают полномочий: автор определяется сервером. Роль `school` сохранена для совместимости; она не может подтверждать выполнение, оценивать поведение или изменять семейные карточки. Клиент скрывает/блокирует соответствующие действия.

Создание участника с уже занятым именем возвращает 409 и не изменяет существующую роль/PIN. Списки возвращаются как `[]`, в том числе на пустой установке. Дата, если указана, должна иметь формат `YYYY-MM-DD`; неверная дата возвращает 400. Если дата отсутствует, используется текущая дата сервера. Неизвестное значение `period` совместимо трактуется как неделя.

Основные статусы: 400 — некорректный ввод, 401 — недействительная сессия/PIN, 403 — недостаточно прав, 404 — объект или допустимое состояние не найдены, 409 — конфликт, 500 — внутренняя ошибка. Детали SQL и внутренних ошибок пишутся в серверный лог, клиенту возвращается общее сообщение. JSON-запрос должен содержать ровно один документ.

Ограничения тела: обычный API — 1 MiB, семейные карточки — 2 MiB, импорт backup — 64 MiB. Nginx ограничивает вход на `/api/session`: 5 запросов в минуту на адрес соединения, burst 5, превышение — 429. За обратным прокси несколько пользователей могут иметь один такой адрес. Внешний proxy может применять дополнительный лимит и меньший максимальный размер тела.

Детали семейных карточек и сценариев: [Семейная жизнь](family-life.md).

Даты отметок семейных карточек и спортивных записей не могут быть позднее текущей даты Europe/Minsk (UTC+3). Это тот же календарь, который используется для дневных учебных наград. Дата планируемого приключения может быть будущей.

## Обучение и дополнительные награды

- `GET /api/math` — до 100 последних собственных занятий, только роль child.
- `POST /api/math` — начать/возобновить единственное активное занятие ребёнка.
  Поля: `operation` (`+`, `-`, `*`, `:`), `level` (`easy`, `medium`, `hard`,
  `columnar`), `answerMode` (`input`, `choice`), `divisionMode` (`result`, `steps`,
  `full`), `allowNegative` (boolean). В столбик допускается только `input`.
- `POST /api/math/{id}/answers` — `{index, values}`; `values` содержит числа по
  ключам `fields` текущего вопроса. Сервер проверяет все шаги и сам назначает
  награду. Повтор уже принятого индекса возвращает сохранённое состояние.
- `POST /api/math/{id}/finish` — закончить досрочно с сохранением ответов/наград.
- `GET /api/activity-rewards` — последние 200 собственных начислений, parent/child.

Все маршруты требуют сессии. Ответы математики содержат только текущий вопрос,
накопленные итоги и разбор последнего отвеченного вопроса, без будущих решений.
Другой ребёнок не может читать/изменять чужое занятие. Школьная роль доступа не имеет.

Правильный ответ в новых занятиях приносит 2–6 ⭐ по сложности, операции и способу ввода, но не более 40 ⭐ суммарно за день (Europe/Minsk). `feedback.correct=true` совместим с `feedback.stars=0` при исчерпании бюджета. Последний бонус может быть частичным. Лимит общий для всех математических занятий и устройств. Backup v6 хранит `mathSessions[].rewardVersion=3`; версии 0 и 2 сохраняют прежнюю шкалу, версия 2 — лимит 30 ⭐. Старые резервные копии v1–v5 поддерживаются только в домашнем режиме.

### Чтение и звёзды

`POST /api/reading/complete` доступен только ребёнку. Тело: `{"id":"0123456789abcdef0123456789abcdef","level":"phrases"}`. `id` — уникальный идентификатор завершённого занятия, 32 строчные шестнадцатеричные цифры. `level`: `phrases`, `sentences`, `advanced`. Ответ — `ActivityReward` с `source=reading`, `sourceKey=id`, серверной датой, названием и фактическими звёздами. Участник берётся из авторизации; величину награды клиент не задаёт.

За шесть прочитанных карточек: 6 / 9 / 12 ⭐ по уровням, до 30 ⭐ за день по Минску, отдельно от математики. Это самостоятельная отметка о практике, не автоматическая проверка чтения. Сервер не проверяет произношение или длительность занятия. Повтор с тем же `id` возвращает исходную награду, даже после полуночи; другой уровень для этого `id` даёт 409. Нулевые начисления также сохраняются, чтобы повтор не получил звёзды на следующий день. Новый проход шести карточек получает новый `id`; повторять материал можно в пределах дневного лимита.

### Устройства и подтверждение родителя

- `POST /session`: `{participantId,pin,remember?,deviceName?,parentId?,parentPin?}`.
  При `remember=true` возвращает `{participant,token:"",remembered:true,deviceId}` и
  устанавливает HttpOnly-cookie. У ребёнка обязательны `parentId,parentPin`.
  Без запоминания возвращается временный bearer; старая cookie-привязка отзывается.
- `GET /session`: проверяет текущий bearer или cookie и возвращает профиль.
- `POST /session/logout`: отзывает cookie этого браузера, удаляет cookie; клиент
  дополнительно удаляет временный bearer. Идемпотентный выход не требует действующей сессии.
- `POST /session/confirm`: текущий parent, `{pin}` → `{proof}` на 5 минут.
- `GET /devices`: parent; активные устройства семьи без секретов, поле `current`.
- `DELETE /devices/{id}`: parent + `X-FamilyQuest-Confirmation: proof`; отзыв только указанного устройства.

Заголовок `X-FamilyQuest: 1` обязателен для cookie-входа и маршрутов входа/выхода/
подтверждения. Origin должен соответствовать Host. Все API-ответы имеют `Cache-Control:
no-store`. На смене PIN и POST /backup обязателен `X-FamilyQuest-Confirmation`;
без актуального подтверждения возвращается 403. PIN-подтверждение не является
токеном входа. При 401 от /session/confirm текущая сессия не сбрасывается.

## SaaS и возрастные настройки

- `GET /api/config` → `{saas: boolean}` без входа.
- `POST /api/account/login` → сессия владельца семьи, тело `{email,password}`. Ограничение тела 4 KiB, пять попыток в минуту на нормализованную почту; Nginx также ограничивает IP. Ошибка входа не раскрывает наличие аккаунта.
- `POST /api/session` в SaaS переключает профиль только внутри уже авторизованной семьи. Старый токен без familyId не принимается.
- `GET /api/subscription` — parent; семья, план, лимит/занятые места, срок, признаки оплаты и доступа. Адрес владельца не возвращается.
- `GET /api/participants/{id}/learning` — parent или сам ребёнок; `{birthDate,mathLevel,readingLevel}`.
- `PUT /api/participants/{id}/learning` — parent; дата `YYYY-MM-DD` или пустая, override математики `easy|medium|hard|columnar`, чтения `phrases|sentences|advanced`, пустая строка означает выбор по возрасту.
- `GET /api/learning-policy` — политика текущего ребёнка. Возраст вычисляется сервером по Europe/Minsk; уровень фиксируется при начале нового занятия.
- `POST /api/reading/start` — ребёнок, `{id,level}` как у завершения. В SaaS обязателен до `/reading/complete`; подмена владельца/уровня запрещена. Изменение возраста после старта не отменяет выбранный уровень. Одновременно до 20 незавершённых стартов; старые старты очищаются при следующем старте через 24 часа.

Истёкший доступ оставляет чтение данных и блокирует новые изменения (403). Ответы/завершение уже начатой математики и переключение сессии разрешены. Приостановленная семья не проходит авторизацию. Доступно [самостоятельное создание семьи после OIDC-входа и изменение названия](self-registration.md). Платежи и возвраты выполняются [оператором](saas-operations.md), публичного billing API нет. Импорт SaaS принимает только backup v6 своей семьи и не восстанавливает финансовый реестр.

## Версия приложения

`GET /api/version` — публичная информация работающей сборки в домашнем режиме и SaaS: `{version,commit,builtAt,startedAt}`. Кэширование запрещено. В режиме Access ответ также содержит объект `access` с версией шлюза; отдельный `GET /api/access/version` возвращает его build metadata. Приватные `/api/__access/*` извне закрыты. Версия продукта не совпадает с номером JSON-backup. [Порядок выпуска и проверки](releases.md).

## MCP и делегирование ИИ-агенту

- `GET /mcp-grants`: текущий parent → активные подключения семьи; секреты не возвращаются.
- `POST /mcp-grants`: текущий parent + `X-FamilyQuest: 1` и `X-FamilyQuest-Confirmation` → `{grant, token}` (201). Тело: `{participantId, name, readOnly}`. `readOnly` по умолчанию `true`; профиль `school` всегда только читает. Срок — 90 дней. Требуется активная подписка.
- `DELETE /mcp-grants/{id}`: текущий parent + `X-FamilyQuest: 1` → отзыв. Доступен и после истечения подписки.
- `/mcp`: MCP Streamable HTTP на официальном Go SDK. Только отдельный Bearer-ключ MCP, без cookie. Каждый запрос заново проверяет делегирование и профиль; обычные токены браузера не принимаются. GET/DELETE управляются stateless-транспортом SDK.

Все пути выше имеют префикс `/api`. MCP-ключ не даёт доступ к защищённым REST-методам. [Роли, инструменты, подключение и эксплуатация](mcp.md).
