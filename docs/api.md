# API и права

Базовый путь — `/api`. Вход: `POST /api/session` с JSON `{ "participantId": 1, "pin": "<6 цифр>" }`. Ответ содержит `participant` и `token`. Защищённые запросы передают `Authorization: Bearer <token>`.

| Endpoint | Доступ / действие |
| --- | --- |
| `GET /health` | Без входа; 503, если PostgreSQL недоступен |
| `POST /session` | Без входа; проверка PIN и выпуск JWT |
| `GET /participants` | Без входа; активные участники без PIN/хешей |
| `GET /leaderboard?period=day\|week\|month&date=YYYY-MM-DD` | Без входа; общий рейтинг |
| `GET /chores`, `/assignments`, `/tasks`, `/week-plan`, `/behavior-ratings`, `/rewards` | Любая действующая сессия |
| `POST /participants`, `PUT /participants/{id}/pin`, `DELETE /participants/{id}` | Только взрослый; последнего взрослого удалить нельзя |
| `POST /chores`, `PUT /chores/{id}`, `POST /assignments` | Только взрослый |
| `POST /tasks/{id}/complete` | Только исполнитель, состояние pending/needs_work |
| `POST /tasks/{id}/confirm` | Взрослый, чужая выполненная задача, rating от 1 до 5 |
| `POST /behavior-ratings` | parent/child, targetParticipantId другого участника, rating от 1 до 5 |
| `POST /rewards`, `DELETE /rewards/{id}` | Только взрослый |
| `GET /backup`, `POST /backup` | Только взрослый; импорт заменяет все прикладные данные |
| `GET /family`, `POST /family`, `PUT /family/{id}`, `POST /family/{id}/actions` | parent/child; дополнительные правила автора, участника и версии карточки |

Объекты `participantId` и `raterParticipantId`, присланные как автор действия, не дают полномочий: автор определяется сервером. Роль `school` сохранена для совместимости; она не может подтверждать выполнение, оценивать поведение или изменять семейные карточки. Клиент скрывает/блокирует соответствующие действия.

Создание участника с уже занятым именем возвращает 409 и не изменяет существующую роль/PIN. Списки возвращаются как `[]`, в том числе на пустой установке. Дата, если указана, должна иметь формат `YYYY-MM-DD`; неверная дата возвращает 400. Если дата отсутствует, используется текущая дата сервера. Неизвестное значение `period` совместимо трактуется как неделя.

Основные статусы: 400 — некорректный ввод, 401 — недействительная сессия/PIN, 403 — недостаточно прав, 404 — объект или допустимое состояние не найдены, 409 — конфликт, 500 — внутренняя ошибка. Детали SQL и внутренних ошибок пишутся в серверный лог, клиенту возвращается общее сообщение. JSON-запрос должен содержать ровно один документ.

Ограничения тела: обычный API — 1 MiB, семейные карточки — 2 MiB, импорт backup — 64 MiB. Nginx ограничивает вход на `/api/session`: 5 запросов в минуту на адрес соединения, burst 5, превышение — 429. За обратным прокси несколько пользователей могут иметь один такой адрес. Внешний proxy может применять дополнительный лимит и меньший максимальный размер тела.

Детали семейных карточек и сценариев: [Семейная жизнь](family-life.md).

## Обучение и дополнительные награды

- `GET /api/math` — до 100 последних собственных занятий, только роль child.
- `POST /api/math` — начать/возобновить единственное активное занятие ребёнка.
  Поля: `operation` (`+`, `-`, `*`, `:`), `level` (`easy`, `medium`, `hard`,
  `columnar`), `answerMode` (`input`, `choice`), `divisionMode` (`result`, `steps`,
  `full`), `allowNegative` (boolean). В столбик допускается только `input`.
- `POST /api/math/{id}/answers` — `{index, values}`; `values` содержит числа по
  ключам `fields` текущего вопроса. Сервер проверяет все шаги и сам назначает
  награду. Повтор уже принятого индекса возвращает сохранённое состояние.
- `POST /api/math/{id}/finish` — закончить досрочно с сохранением ответов/наград.
- `GET /api/activity-rewards` — последние 200 собственных начислений, parent/child.

Все маршруты требуют сессии. Ответы математики содержат только текущий вопрос,
накопленные итоги и разбор последнего отвеченного вопроса, без будущих решений.
Другой ребёнок не может читать/изменять чужое занятие. Школьная роль доступа не имеет.
