# Подготовка общего биллинга LOVIT

Состояние: адаптер реализован и проверяется, production-подключения отсутствуют.
Рекуррентные платежи и чеки НПД согласуются с Robokassa. Платёжная форма LOVIT пока
предварительная: 1 ₽ за первые 7 суток, затем 100 ₽ за календарный месяц, без лимита детей.

## Границы

LOVIT хранит реальные платежи и согласия. FamilyQuest хранит локальную проекцию прав,
а не вторую копию платежей. Ключ продукта может только читать свои права, не подтверждать
оплату или обращаться к чужому продукту. Данные карты, OAuth-секреты и PIN в обмен не входят.

Новая family migration 011 добавляет false-поля children_unlimited и billing_managed.
Она не меняет прежние сроки и лимиты. Таблица fq_platform.lovit_bindings содержит только
явно подключённые семьи. Бессрочный доступ, включая семью «Лобовы», не мигрирует и не
начинает оплачиваться. Семьи с прежней историей платежей требуют отдельного плана сверки;
автоматическое подключение к LOVIT для них запрещено.

Access endpoint POST `/api/integrations/lovit/billing-context` использует тот же отдельный
read-only ключ, что и summary. Принимает только issuer+subject, не family ID. Принадлежность
определяется существующей подтверждённой identity-привязкой. Возвращает subjectRef
`familyquest:<id>` для серверного сопоставления и eligibility. Доступ к профилю этим не выдаётся.

## Включение после согласования провайдера

1. Выпустить совместимые версии LOVIT и FamilyQuest. Выполнить штатные operator migrate
   и grant-access с существующим runtime role: новому запросу Paid требуется SELECT новой
   таблицы bindings. Core не получает права чтения аккаунтов/платежей и ключи LOVIT.
2. Подготовить окончательную версию тарифа/согласия в LOVIT: RUB, intro 100 копеек/7 суток,
   месячная цена 10000 копеек, features.children_unlimited=true. Проверить чеки, callbacks,
   платежи, отмену и возврат. Каталожный режим не менять одним флагом до полной проверки.
3. LOVIT разрешает привязку только после получения eligibility=eligible из FamilyQuest
   под issuer+subject текущего плательщика. Сопоставить возвращённый subscription ID
   и familyquest:<id>. Не вводить семейный ID из браузера и не связывать по email/телефону.
4. С операторским DATABASE_URL через stdin выполнить `operator bind-lovit` с объектом
   FamilyID, SubscriptionID, Operator. Команда идемпотентна для той же привязки. На
   действующем/бессрочном/ранее оплаченном доступе — отказ, политика остаётся прежней.
5. Отдельному операторскому процессу предоставить LOVIT_ORIGIN=https://lovit.tech и
   LOVIT_ENTITLEMENT_TOKEN — выделенный ключ только продукта FamilyQuest, из защищённого
   окружения/файла 0600. Не передавать секреты аргументами, в чат или Git.
6. `operator sync-lovit` получает через stdin FamilyID и Operator. Сначала читает
   сохранённый subscription ID, затем проверяет HTTPS-ответ LOVIT и применяет его
   транзакционно. Подмена продукта, семьи, подписки, устаревшее время или revision — отказ.
   Ни HTML-редирект, ни браузерный callback не дают доступ.
7. После тестовой приёмки запустить периодическую сверку для явно подключённых семей
   с контролем ошибок. Планировщик в этой подготовке не устанавливается. До первого
   успешного sync права не выдаются; между синхронизациями локальное истечение срока
   продолжает действовать. Сеть/сбой не дают бесконечный grace period. Более свежая
   отмена/возврат/приостановка из LOVIT применяется на следующей успешной сверке.

Отмена автопродления в LOVIT сохраняет ещё оплаченный период; сама по себе не должна
формировать expired entitlement. После его окончания новые действия блокируются,
история доступна. Ручное внесение новых локальных платежей для связанной семьи запрещено.
Полный отзыв/возврат проецируется только по новой revision. Транспортный timeout ничего
не меняет в policy, исходный срок доступа не увеличивается.

## Проверки

Обязательны выделенная тестовая БД FAMILYQUEST_TEST_DATABASE_URL и `go test -race ./...`.
Сценарии: бессрочный grant и старые платежи остаются прежними; отдельная новая семья
получает период без копирования платежа; можно создать больше прежнего лимита детей;
чужая семья/подписка/продукт, replay, устаревший ответ и redirect отклоняются; потеря
доступа не удаляет профили; UI бессрочной семьи не предлагает новую оплату.
Перед production-включением — снимок семей, аккаунтов, identity, оплат и прежних policy,
проверка сохранности после. Не запускать migrate/bind/sync на production для демонстрации.
